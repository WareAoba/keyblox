# keyblox — MIDI → Roblox 88키 피아노 자동 연주

단일 실행 파일입니다(약 0.9MB). 설치할 필요가 없고, Windows 기본 DLL과 시스템 글꼴(맑은 고딕)만 씁니다.

## 사용법
1. `keyblox.exe`를 실행하고 **MIDI 파일 열기**를 누릅니다. 창이나 exe 아이콘 위에 `.mid` 파일을 끌어다 놓아도 됩니다.
2. 오른쪽 아래 **분석** 카드에서 원래 자리에서 연주되는 음의 비율을 확인합니다.
3. **▶** 버튼을 누른 뒤 Roblox 창을 클릭하면 0.4초 후에 시작합니다. Roblox 안에서는 **F6**(재생/일시정지)과 **F7**(정지)을 씁니다.
4. 진행 바를 클릭하거나 끌면 원하는 위치로 이동합니다.

다른 창으로 전환하면 자동으로 일시정지하고 눌린 키를 모두 뗍니다.

## 설정
| 항목 | 설명 |
|---|---|
| Roblox FPS | 게임 설정의 최대 프레임과 같게 맞춥니다. 높을수록 Shift/Ctrl을 빨리 전환할 수 있어 더 많은 음이 남습니다. |
| 허용 지연 | 화음을 펼쳐 칠 수 있는 최대 시간입니다. **자동**은 흰건반·검은건반·Ctrl 베이스가 한꺼번에 나오는 화음도 다 들어가는 값(전환 간격×2 + 2ms)입니다. − 버튼으로 0 아래로 내리면 다시 자동이 됩니다. |
| 초당 최대 타건 | Roblox 렉 방지용입니다(기본 200, 0이면 무제한). 넘치는 순간에는 최고음(멜로디)과 최저음(베이스)을 먼저 남깁니다. 큰 화음 하나는 그대로 살리고, 오래 이어지는 폭주만 깎습니다. |
| 재생 속도 / 이조 / 페달 / 드럼 | 말 그대로입니다. |
| Roblox 창에만 입력 | 켜 두면 다른 프로그램에 키가 입력되지 않습니다. |
| 비주얼라이저 | 끄면 화면을 그리는 CPU를 아낍니다. |

비주얼라이저 색상: 청록 = 흰건반, 보라 = Shift(검은건반), 주황 = Ctrl(A0–B1, C#7–C8), 회색 = 뺀 음.

## 동작 원리
- **템포**: 모든 트랙의 템포 변화를 정수 연산으로 정확하게 환산합니다. 템포 이벤트 2,159개가 들어 있는 Rush E 파일에서, pretty_midi와 음표 46,291개 전부가 1µs 이내로 일치했습니다.
- **음을 미루지 않음**: 모든 음은 원래 시각(허용 지연 이내)에 칩니다. 그 시각에 칠 수 없는 음은 빼고, 뒤 음을 밀지 않습니다. 어떤 음을 남길지는 곡 전체를 한 번에 계산해서 고릅니다.
- **유일한 시간 제약 — Shift/Ctrl**: Roblox는 프레임마다 키를 처리하면서 그 순간의 Shift/Ctrl 상태로 음높이를 정합니다. 그래서 수식키 상태를 바꿀 때만 약 1프레임을 기다립니다. 같은 상태의 키는 간격 제한 없이 보냅니다.
- **재생 엔진**: 키 입력 순서는 미리 다 계산해 둡니다. 1ms 이내에 몰린 입력은 SendInput 한 번으로 묶고(Roblox는 어차피 프레임 단위로 처리), 스레드 우선순위는 HIGHEST로 두되 대기 중에는 CPU를 양보합니다. 키는 물리 스캔코드로 보내므로 JIS 키보드 설정이어도 같은 위치의 키가 눌립니다.
- **화면**: WebView 같은 브라우저 엔진 없이 순수 Rust 소프트웨어 렌더러로 그립니다. 변하지 않는 부분은 캐시해 두고, 매 프레임 바뀌는 부분만 다시 그립니다. Rush E의 가장 빽빽한 구간에서도 프레임당 약 2ms(1배 배율)가 걸립니다.

## 결과 예
| 곡 | 60fps, 기본 설정 |
|---|---|
| Unravel (Animenz) | 3,436음 중 0개 뺌 (60–240fps 모두) |
| Rush E | 초당 200타 제한 때문에 끝부분 폭주 구간이 깎임: 유지율 25% (제한 없으면 68%) |

## 빌드
```
cargo build --release
```
`target\release\keyblox.exe`가 만들어집니다(MSVC·GNU 툴체인 모두 지원, 매니페스트는 build.rs가 자동으로 넣음).

```
cargo test --release
```
템포 환산·키맵·스케줄러 테스트(무작위 곡 스트레스 포함)를 돌립니다.

Windows가 아닌 환경에서는 분석과 화면 미리보기(PNG)만 됩니다:
`keyblox 곡.mid --preview out.png --at 60`

## 폴더 구조
| 파일 | 역할 |
|---|---|
| `src/midi.rs` | MIDI 파싱, 템포맵 → µs 환산 |
| `src/layout.rs` | 88키 ↔ 키보드 스캔코드 배치 |
| `src/schedule.rs` | 칠 음 고르기(DP), 타건 제한, 키 입력 타임라인 생성과 검증 |
| `src/analyze.rs` | 불러오기 + 스케줄 + 요약 |
| `src/player.rs` | 실시간 재생 엔진(SendInput), 핫키 (Windows) |
| `src/ui.rs` | 화면 모델·레이아웃·소프트웨어 렌더러 (OS 무관) |
| `src/gui.rs` | Windows 창 셸 |
| `res/` | Windows 매니페스트 |
